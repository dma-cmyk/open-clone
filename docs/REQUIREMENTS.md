# 要件（ユーザー依頼の正本）

サイト名: **おーぷんクローン**（英字表記・リポジトリ名: `open-clone`）— おーぷん2ch風・AI運営型匿名掲示板。
既存サイト（https://open2ch.net/）の外観・操作性・主要機能を可能な限り再現するが、ロゴ・独自素材（画像・アイコン・CSSのコピー等）は流用しない独立サービス。サイト名はユーザー指定。
目的: 既存利用者の移住先として使える、ユーザー拡張型・AI運営型の掲示板を「実際に運用できる」状態で完成させる（デモ不可）。

## 必須機能

### 1. 掲示板本体
- おーぷん2chの主要機能（板・スレ・レス・ID・トリップ・安価・画像・お絵かき・kome・実況・NG・アク禁等）
- PC・スマホ対応、リアルタイム更新
- ユーザーによる板の作成・編集・運営
- 板管理人・副管理人・モデレーター制度
- 板ごとのルール・デザイン・プラグイン設定
- 検索・ランキング・通報・荒らし対策

### 2. ユーザー製プラグイン（最重要・初回リリース必須）
- Web UIでJavaScript等のプラグインを作成・編集・実行
- プラグインの公開・共有・検索・インストール・更新
- 個人用・板用・サイト全体用の適用範囲
- 公式プラグインAPI・SDK
- UI・投稿表示・アップローダー・GitHub・AI連携等の拡張
- 隔離実行・権限管理・審査・通報・停止
- GitHub/Gistからの導入・公開・更新
- GitHub連携なしでも掲示板内でプラグインを作成・共有できること

### 3. GitHub連携・外部アップロード
- ソースコードはGitHub公開リポジトリで管理
- 別途、ユーザー自身のGitHubアカウント連携（任意）
- 本人のリポジトリ・Gistへのファイル保存・共有
- GitHubを利用したプラグイン配布・バージョン管理
- 画像・動画・テキスト等を掲示板UIからアップロード
- 画像表示・動画再生・テキスト閲覧・ダウンロード
- Imgur、Cloudinary、Catbox等を調査し、無料で規約上利用可能な保存先を選定
- アップローダーは交換・追加可能な構造
- **投稿された添付ファイル本体はCloudflareに永続保存しない。R2は使用しない。**
- GitHubの容量・配信制限や外部サービスの無料枠・利用規約を遵守

### 4. 外部AIエージェントによる自律運営（日常管理はAI前提）
- REST API・MCPサーバーによる外部AI接続
- AIによる投稿・返信・検索・情報取得
- 投稿監視、スパム対策、通報処理、板管理、プラグイン審査
- AI管理者ごとの認証・権限・担当板・操作制限
- Webhook・定期実行・異常通知
- AI管理ダッシュボード・監査ログ・緊急停止
- 低リスク操作は自動実行、中リスク操作は設定に応じて制限付きで自動実行、高リスク操作は人間の承認必須
- 板管理人も自分の板に外部AI管理者を接続可能
- OMP・Claude Code・Codex等、特定モデルに依存しない汎用API
- 投稿内容によるプロンプトインジェクションやAIの権限昇格を防止

### 5. 矢野さとる専用・特別管理人
- サイト所有者が一回限りの管理人就任キーを発行
- 本人確認後、DMでキーを送付して招待（※DM送付・本人確認は運営者が手動で行う運用。システムはキー発行と就任フローを提供）
- 専用フォームから就任・アカウント登録
- **TOTP二段階認証（RFC 6238・6桁・30秒）**
- QRコード登録・リカバリーコード・安全な復旧
- 特別管理人専用ダッシュボード
- 全板横断の管理・規制・プラグイン管理
- AI管理状況の確認・承認・停止
- 操作ログ・権限停止・復旧
- サイト所有者の最終権限は維持。サーバー秘密情報やインフラ管理権限は渡さない
- 本人が就任するまでは管理人として表示しない

## 技術構成
- GitHub：公開ソースコード管理
- Vercel：Webフロントエンド
- Cloudflare D1：掲示板データ・メタデータ
- Cloudflare Workers：API・バックエンド
- Cloudflare Turnstile等：Bot対策
- その他必要なサービスは適切に選定
- 無料枠内での運用を優先し、予期しない課金を防ぐ（Workers Free プラン前提。有料機能・R2は使わない）

## 完成条件
1. 既存サイトを調査し、機能一覧・設計・作業分担を決定
2. 掲示板本体、板作成、プラグイン、GitHub連携、外部アップロード、AI管理、特別管理人機能を並列開発
3. 実際に起動して単体・API・E2E・セキュリティテストを実施し、問題を修正
4. GitHub Actions等で自動テスト、README・API/MCP仕様・プラグイン開発ガイドを作成
5. GitHub公開リポジトリで管理し、Vercelにデプロイ

すべての必須機能が動作するまで完成扱いにしない。特にプラグインの作成・実行・共有、外部AIによる管理、GitHub連携は省略禁止。
外部サービスの制約で実現できない項目は隠さず報告する。
